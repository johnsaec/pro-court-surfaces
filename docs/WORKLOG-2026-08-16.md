## 1. Hardened external-service clients (Resend + Stripe)
**Commits:** doc + `29658c1`
**Why:** The Resend and Stripe clients were constructed at *module-load time*
(`export const resend = new Resend(process.env.RESEND_API_KEY)`). A missing/bad
key threw at **import**, crashing the whole route/page before any handler ran —
which (a) defeated the new lead safety net and (b) broke the prod build on
`/q/[share_token]`.
**What:** Made both lazy — `getResend()` / `getStripe()` construct on first use
and cache. A bad key now fails at *call time* (caught by existing try/catch), not
import. No behavior change when keys are present.
**Verified:** `tsc` clean · `next build` passes with no keys · `POST /api/leads`
returns 200 with no Resend key (email fails gracefully).
Details: [`RESEND-STRIPE-INIT-FIX.md`](./RESEND-STRIPE-INIT-FIX.md).

## 2. Email-fallback safety net on the lead form
**Commit:** `f0ea221` · file `src/app/api/leads/route.ts`
**Why:** If the DB save fails, a prospect must not be silently lost.
**What:** On DB failure the API no longer bails — it still sends the admin
notification email (stamped **⚠️ NOT SAVED TO CRM — follow up manually** + the
error) and returns a degraded success so the prospect isn't told to retry. A real
error is only returned if **both** the DB and the notification email fail. Happy
path (insert/update) unchanged.

## 3. Diagnosed + fixed "Failed to save lead"
**Why:** The public contact form was erroring for prospects.
**Root cause:** The **Supabase project was paused** (free-tier auto-pause after
~7 days idle) → database offline → every insert failed. It was **not** a code or
schema bug.
**Fix:** Restored the project, then **upgraded Supabase to Pro** so it won't
auto-pause again. Confirmed live: DB reachable, and a real end-to-end form
submission saved a full 43-field record (incl. the step-2 court assessment) and
fired the admin email.
**Note:** Leads submitted during the pause window were lost (insert failed before
the notify email) — the safety net in §2 prevents a repeat.
